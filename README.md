# 도술 연계도

도깨비의 세계의 도술 105개를 바탕으로 사용 순서, 효과 연계, 개방 신식, 반복 실행 시간을 확인하는 웹 도구입니다.

운영 사이트: https://dokkaebi-dosul-lab.spunkyloom17.chatgpt.site/

## 실행

Node.js 20 이상이 필요합니다. 외부 패키지를 설치할 필요는 없습니다.

```powershell
npm run dev
```

브라우저에서 http://127.0.0.1:5173/ 을 엽니다. `npm`이 없다면 `node scripts/serve.cjs`로도 실행할 수 있습니다. 다른 포트는 PowerShell에서 `$env:PORT=5174`로 지정합니다.

```powershell
npm test
```

전체 검증을 실행합니다. 대안은 `node scripts/test.cjs`입니다.

## 에이전트용 일괄 시뮬레이션 비교

```sh
node scripts/compare-builds.cjs --verify
```

서버나 브라우저 없이 앱과 같은 엔진으로 7개 단일 방어 구성 × 4개 환경 × 60/120/180초를 비교합니다. JSON 설정으로 다른 빌드와 관찰할 효과를 지정할 수 있습니다. 결과 JSON·CSV·요약·가져오기용 빌드·판정 로그는 `reports/` 아래에 생성됩니다. `npm run compare -- --verify`도 가능합니다.

상세 설정과 다른 에이전트를 위한 해석 규칙은 [비교 실행기 사용법](comparisons/README.md)을 참고하세요. 실제 생존 시간이나 보호막 유지율은 계산하지 않습니다.

## 소스 구조

빌드 과정이 없는 정적 앱입니다. **`dist/`가 직접 편집하는 원본 소스이자 배포 디렉터리**입니다.

- `dist/index.html`: 상단 탭과 화면 구성
- `dist/planner.js`, `sequence.js`: 8개 일반 도술 + 궁극기 1개, 장착·순서·저장
- `dist/data.json`, `data.js`: 도술 원자료와 브라우저용 데이터. 데이터 수정 시 두 파일을 함께 갱신해야 합니다.
- `dist/graph.js`: 효과 연계 그래프
- `dist/combat.js`, `hit-timing.js`, `timing-auto.js`: 개방 신식·쿨타임·타격 시점 계산
- `dist/timing-ui.js`: 반복 실행 간트차트
- `dist/simulation.js`: 공간 전투 엔진 (영상 기반 배치 4종, 적중·효과·조건 판정). 빌드 최적화와 비교 실행기가 사용합니다.
- `dist/optimizer.js`, `optimizer-ui.js`, `optimizer.css`: 빌드 최적화 탭 (회복·보호막 파서, 보호막 지속시간 모델, 탐색, 재검증)
- `dist/kkaebigg/`, `dist/kkaebigg.js`, `scripts/kkaebigg-sync.cjs`: 깨비지지 자료 고정본, 엔진 적용·버프 연결, 동기화
- `dist/kkaebi-gg/hunting.json`: kkaebi.gg 사냥터 21곳·몬스터 385종 능력치와 깨비지지 출현 좌표 연결
- `dist/kkaebi-gg/skills-aim.json`, `scripts/apply-kkaebi-gg.cjs`: kkaebi.gg 도술별 사거리·조준 방식 고정본과 `data.json`/`data.js` 반영 (`npm run aim`)
- `dist/simulation-evidence/`: 엔진 배치 4종의 근거가 된 사냥 영상 장면·체력 이미지 (원본 영상은 보관하지 않음)
- `dist/icons/`: 로컬 도술 아이콘
- `dist/builds/`: 불러올 수 있는 빌드 JSON 예시
- `*.test.cjs`, `scripts/test.cjs`: 계산 및 UI 상태 회귀 검증
- `.openai/hosting.json`: 기존 Sites 프로젝트 연결 정보. 인증 토큰은 포함하지 않습니다.

현재 조합과 저장 빌드는 브라우저의 localStorage에 보관합니다. **운영 사이트와 로컬 사이트는 저장소가 다르므로** 기존 빌드를 옮기려면 운영 사이트의 `저장·파일 → JSON 내보내기` 후 로컬에서 가져오세요.

## 전투 엔진

화면은 없고, 빌드 최적화와 비교 실행기가 `dist/simulation.js`를 직접 호출합니다. 2026-10-17의 `183432`, `184555`, `185547`, `190057` 녹화를 근거로 한 벽가·원형 외곽·중앙 밀집 배치 4종에서 시전 순서, 공간 적중, 대상 상한, 같은 몹에 남은 약화 효과, 쿨타임·충전·개방 신식을 계산합니다.

가상 배치의 거리·12마리·이동 속도·20초 재배치는 비교용 가정입니다. **실제 처치량, DPS, 체력, 생존 시간은 산출하지 않습니다.** 미확인 공격 형상과 장판 타격 간격은 계산에서 제외합니다. 기본 피해계수 전달량은 실전 피해량이 아닙니다.

모델 `spatial-no-hp-v4` (2026-10-18 엔진 감사):
- 20초 재배치 직전에 시작한 시전의 타격이 사라진 대상을 노려 빈 타격이 되던 문제를 고쳤습니다. 새 배치에서 가장 가까운 몹을 다시 겨눕니다. 무작위 빌드 기준 피해계수가 평균 1.5%(최대 5.7%) 덜 잡혔습니다.
- 같은 순간에는 앞 시전의 마지막 타격·종료를 다음 시전 시작보다 먼저 처리합니다. 앞 시전의 타격이 다음 시전이 시작 때 거는 버프를 받던 판정을 막습니다.
- 효과 부여·만료와 조건·적중 기록 시각을 0.01초로 반올림하지 않습니다. 반올림 때문에 같은 순간의 효과가 미래로 밀리던 판정 오류를 막습니다.
- 자기 버프 조건(예: 기세 보유 중 적중)은 여러 몹을 맞혀도 타격 1회당 한 번만 판정합니다. 이전에는 맞힌 몹 수만큼 기록되어 범위 빌드의 회복·보호막이 부풀려졌습니다.
- 효과 기록의 배치 번호를 다른 기록처럼 1부터 셉니다. 적중 기록의 `targets`는 몹 id(0부터), 조건·효과 기록의 `target`은 몹 번호(1부터)입니다.
- `engine-invariants.test.cjs`가 모든 계열의 무작위 빌드 × 배치 4종 × 60/180초에서 시간표·충전·우선순위·타격·조건·신식·집계·결정성을 로그로부터 다시 계산해 검사합니다.

## 도술 조준 방식 (kkaebi.gg)

[kkaebi.gg 도술 도감](https://kkaebi.gg/skills)의 도술별 상세 페이지 105개에서 사거리와 조준 방식(대상 지정·자신 중심·방향 지정·지면 지정·지면 이동), 대상(적·자신·아군), 충전, 시전 시간, 연계 도술을 2026-10-18에 수집해 `dist/kkaebi-gg/skills-aim.json`에 고정했습니다. 사이트가 비브라우저 요청에 429로 응답해 자동 동기화는 없습니다. 브라우저에서 1.5초 간격으로 한 번씩 받았습니다.

`npm run aim`이 각 도술에 `aim`을 기록합니다. 엔진은 근거를 확인한 형상(`simulationGeometry`, 설명·툴팁 기반 형상)이 없을 때만 이 방식으로 공격 형상을 정합니다.

- 자신 중심 → 시전자 주변 원형, 반경 = 사거리
- 방향 지정 → 전방, 길이 = 사거리. 설명에 경로·직선·관통이 있으면 직선, 아니면 120° 부채꼴(각도 가정)
- 지면 지정·지면 이동, 대상 지정 범위 → 지점/대상 주변 원형, **반경 2m 가정**. 설명의 "주위 적 N명"은 대상 수 상한으로 사용
- 최대 대상 수(N인)와 범위 반경은 kkaebi.gg에도 없어, 공식 표기가 없는 도술은 기존처럼 5인을 가정합니다.

이로써 공격 형상을 몰라 피해 계산에서 빠지던 도술이 37개에서 0개가 되었습니다. 궁극기 5개(신내림·대폭발·방패 낙하·회전하는 칼날·개전의 가호)의 재사용 대기시간은 10월 10일 공식 안내 대신 kkaebi.gg와 깨비지지가 일치하는 게임 자료 값으로 바꿨습니다.

## 사냥터·몬스터 (kkaebi.gg)

`dist/kkaebi-gg/hunting.json`은 [kkaebi.gg 전투력별 사냥터](https://kkaebi.gg/hunting)의 사냥터 21곳(연무림 8,480 ~ 고갯마루 960,000)과 몬스터 385종을 2026-10-18에 고정한 자료입니다.

- 사냥터: 권장 전투력, 세부 구역별 권장 전투력, 레벨, 마리당 엽전
- 몬스터: 레벨·체력·공격력·방어력·엽전
- 출현 지점 수와 좌표(지도 대비 %)는 같은 사냥터 id로 깨비지지 맵 도감 고정본에서 연결했습니다.

몬스터 공격력은 있지만 받는 피해 공식(방어력·회피 반영)과 공격 주기는 공개되지 않아, 받는 피해는 여전히 실측으로 정합니다. 예를 들어 독기 지대(공격력 7,888/8,555)에서 방어력 19,467일 때 실측 피격은 1회 2,055/2,597이었습니다.

## 빌드 최적화

`빌드 최적화` 탭의 목표는 하나입니다: **물약 없이 버틸 수 있는 범위에서 스킬 파워(목표 사냥터 분당 처치 수)가 가장 큰 9칸 구성**을 찾습니다. 순서 구성의 현재 빌드가 출발점이며, 버튼 하나로 추천 빌드 카드(사용 순서·기본 장착, 물약 없이 버팀 여부와 분당 여유, 현재 대비 스킬 파워 %, `이 빌드 적용`(되돌리기 가능)·JSON 저장)를 보여 줍니다. 추천 카드 아래 `비슷한 빌드 보기`(지금 빌드에서 도술 0~3개 교체)와 `다른 도술 조합 보기`(4개 이상 교체)가 따로 접혀 있고, 각각 상위 10개까지 도술 조합마다 가장 좋은 순서·기본 장착 하나로 보여 줍니다. 모든 빌드에는 왜 바꿨는지를 한 줄로 요약합니다. 추가한 도술마다 이유(다른 도술이 필요로 하는 효과를 거는지 → 이미 걸리는 효과를 활용하는지 → 자체 회복·보호막 → 피해 계수·쿨 순으로 데이터에서 찾음)를 괄호로 붙이고, 순서를 바꿨다면 효과를 거는 도술을 그 효과가 필요한 도술 앞으로 옮겨 발동 횟수가 늘었는지, 아니면 같은 180초에서 쿨타임 대기 시간이 줄었는지를 시뮬레이션 수치로 적습니다. 대신 채운 회복·보호막, 몹 몰이, 여유도 함께 적습니다.

**분석용 내보내기**: 결과 아래 `분석용 내보내기 (.md)`·`분석용 텍스트 복사`. 목표·계산 방식·보정값·한계, 캐릭터와 사냥 기준, 현재 빌드·추천·비슷한 빌드·다른 도술 조합 각각의 사용 순서(계열·단일/범위·쿨), 기본 장착, 분당 처치·몹 수·받는 피해·회복·보호막·필요량·여유·쿨타임 대기, 이유 한 줄, 도술별 회복·보호막 표를 Markdown으로 담고, 끝에 같은 수치를 JSON(`dosul-optimizer-analysis-v1`)으로 붙입니다. 프롬프트에 그대로 붙여 넣어 분석을 요청할 수 있도록 분석 요청 예시도 들어 있습니다. 탐색은 지금 빌드 근처 3줄기와, 도술 4개 이상을 바꾼 상태를 유지하는 먼 탐색 2줄기로 나눠 진행합니다.

1. **내 캐릭터**: 최대 체력·공격력·체력 자연 회복. 회복·보호막 수치가 이 값에 비례합니다. 자연 회복은 전투 중 5초 주기(게임 상수)로 고정합니다. 방어력·회피 등은 입력하지 않습니다(실측값에 이미 들어 있음).
2. **사냥 기준**: 기본은 `사냥 실측` — 현재 빌드로 몇 분 사냥한 `측정 사냥터`, 시작/끝 HP, 측정 시간(초). `받는 피해 = 현재 빌드의 회복·보호막 + 자연 회복 − 순 체력 변화`로 역산하며, 끝 HP가 최대치나 0에 닿으면 계산하지 않습니다. 측정 방법(물약 끄기, HP 50~70%에서 시작, 전투 유지, 측정 중 변경 없음)은 화면의 `측정 방법`에 있습니다. 받는 피해를 알면 `분당 받는 피해 직접 입력`을 고릅니다.
   - **목표 사냥터**: 측정한 곳과 다르면 출현 지점 수로 가중한 몬스터 평균 공격력의 비율만큼 받는 피해를 환산합니다(예: 독기 지대 → 마을 폐허 ×1.65, 추정). 권장 전투력·몬스터 레벨·평균 체력·공격력을 보여 주고, `내 전투력`을 넣으면 권장치 대비 비율을 표시합니다. 자료는 `dist/kkaebi-gg/hunting.js`(`npm run hunting`으로 `hunting.json`에서 생성)입니다.
   - 필요량 = 받는 피해 − 자연 회복 + 안전 여유 1,000(분당). 현재 빌드가 버티는지도 함께 표시합니다.
3. **쓸 수 있는 도술**: 열린 신식 계열(기본값은 현재 빌드의 계열). 범위 공격 도술도 후보이며, 끌어오는 몹 수만큼 받는 피해가 늘어난 상태로 판정합니다. 탐색은 4,000회로 고정입니다.

### 몹 수와 처치 속도 (사냥 모델)

선공 몹이 없으므로 맞힌 몹만 덤빕니다. 단일 도술만 쓰면 항상 1마리, 범위 공격 도술은 범위 안 몹을 함께 끌어옵니다.

- **몹 밀도**: 사냥터 출현 좌표(지도 %, `hunting.js`)를 미터로 바꿔 몹 주변 12m 안의 평균 몹 수 ÷ 면적으로 구합니다. 범위 도술 1회가 끌어오는 몹 = 밀도 × 범위 면적(원형·대상 중심은 반경, 직선은 길이 × 1.3m, 부채꼴은 120°), 대상 수 상한까지.
- **처치 속도**: 사용 순서의 시전 시각대로 단일 피해는 한 마리에 집중하고, 범위 피해는 붙은 몹 모두에게 들어갑니다. 한 마리가 죽으면 바로 다음 몹과 싸웁니다. 결과: 분당 처치 수(스킬 파워)와 동시에 붙은 몹 평균.
- **받는 피해** = 1마리당 받는 피해 × 동시에 붙은 몹 평균. 실측은 측정한 빌드의 평균 몹 수로 나눠 1마리 기준으로 바꾸고, 목표 사냥터 공격력 비율을 곱합니다. 필요량은 빌드마다 따로 계산됩니다.
- **보정값** (2026-10-18 독기 지대 녹화 5개): 지도 1px ≈ 0.95m — 불굴 5m 원(1492px 화면에서 지름 456px)으로 화면을 약 32.7m × 26.8m로 재고, 화면 속 몹 약 7~9마리와 맞췄습니다(마을 폐허 영상의 10~12마리와도 일치). 실제 피해 ≈ 계수 × 공격력 × 0.155 — 대상 체력바로 잰 단일 빌드 처치 속도(분당 약 9~11마리, 몹 체력 약 45,000)와 맞췄습니다. 몹 방어·치명타·몹 사이 이동 시간이 이 값에 들어 있습니다.
- **한계**: 043203 녹화의 범위 빌드는 실제 분당 약 −42,000이었고 모델은 −11,000으로 부족을 맞혔지만 크기는 작게 봅니다. 보호막 흡수(검증 전)와 사냥 지점의 실제 밀도가 남은 오차의 후보입니다. 몹이 다가오는 시간과 재출현 대기는 빠져 있습니다.

`계산 근거 보기`에는 깨비지지 동기화, 현재 빌드의 회복·보호막 표(실측 1회량 입력), 계산 제외 목록, 계산 기준과 한계가 있습니다.

회복·보호막은 도술 설명의 `공격력의 X% + N`, `최대 체력 X%`, 고정값, `최대 N회`를 읽어 계산합니다. 조건부 효과는 시뮬레이션에서 조건이 성립한 적중만, 무조건 효과는 완료 시전마다 셉니다. 게임에서 확인한 1회량이 다르면 `실측 1회량`에 입력합니다.

받는 피해를 알면(직접 입력·실측) 보호막과 받는 피해 감소는 깨비지지 버프 사전의 **지속시간·중복 규칙**으로 계산합니다. 피해가 일정하게 들어온다고 보고 감소 → 먼저 끝나는 보호막 순으로 막으며, `교체` 규칙의 보호막이 다시 걸리면 남은 양은 버려집니다. 예를 들어 휘둘러 내려치기의 낙인 보호막은 3회 타격이 서로 교체해 최대치의 절반 이하만 흡수됩니다. 실측 역산은 흡수량이 받는 피해에 따라 달라지므로 수렴할 때까지 반복합니다. 같은 이름의 버프가 여러 지속시간 후보를 가지면 계산하지 않고 목록으로 표시합니다.

도술 수는 유지합니다. 궁극기는 지금 것과 체크한 계열의 궁극기를 모두 시도하며(척살·제압처럼 체크하지 않은 계열은 제외), 궁극기를 바꾸면 그 계열 도술 3개를 넣고 기본 장착 조건을 맞춥니다. 궁극기 교체는 먼 탐색의 한 줄기와 다듬기에서만 시도하고, 결과 그룹마다 같은 궁극기는 3개까지만 보여 줘 여러 궁극기가 함께 보이게 합니다. 탐색은 영상 03 배치·180초에서 진행하고, 상위 후보를 4개 배치 × 60/120/180초로 다시 계산해 가장 나쁜 값이 기준을 넘는 구성만 표시합니다. 결과는 비교 모델의 판단이므로 실제 사냥으로 확인하세요.

## 깨비지지 자료 동기화

`dist/kkaebigg/`는 [깨비지지](https://kkaebigg.com/)의 공개 자료 고정본입니다. 도술 수치(`/data/skills.json`), 버프 사전(지속시간·중복 규칙·단계별 수치), 맵 도감(구역·출현 좌표), 몬스터 도감(레벨·체력·사냥터)과 원본 버전·수집 시각·SHA-256(`meta.json`)이 들어 있습니다.

- 페이지를 열면 `kkaebigg.js`가 고정본을 엔진 데이터에 적용합니다. `data.json`은 같은 원본에서 만들었으므로(깨비지지 id N = `s`+N+1) **값이 다른 항목만** 바꿉니다. 재사용 대기시간이 바뀌면 시뮬레이션의 `basic.cooldown`도 바꿉니다. 바뀐 건수는 빌드 최적화 탭의 `계산 근거 보기`에 표시합니다.
- **동기화**: 빌드 최적화 탭 `계산 근거 보기`의 `깨비지지 동기화` 버튼, 또는 `npm run sync`. 깨비지지가 CORS를 허용하지 않아 버튼은 로컬 서버(`npm run dev`, 바탕화면 아이콘)의 `POST /api/kkaebigg/sync`로 받아옵니다. 정적 배포 사이트에서는 동작하지 않습니다. 완료 후 새로고침하면 적용됩니다.
- 네 자료를 모두 받아 형식을 검사한 뒤 한꺼번에 교체합니다. 하나라도 실패하면 기존 고정본을 그대로 둡니다. 사용자가 누를 때만 요청하며 `dokkaebi-dosul-lab` 사용자 에이전트를 보냅니다.
- 비공식 자료이므로 현행 인게임 값과 다를 수 있습니다. 맵·몬스터 자료는 아직 엔진에서 사용하지 않습니다.

## 배포

다음 도술 후보는 스킬 정보의 효과 지속시간을 읽어, 후보 첫 사용의 개별 적중 시점에 효과가 남는지 평가합니다. 만료·효과 없음·종료 경계·지속시간/시점 미확인·추가 조건 미확인은 연계 점수에서 제외합니다. 일부 타격만 시간 내에 들어오면 그 비율만 점수에 반영합니다. ‘연계 후보만’은 만료 연결을 제외하지만 판정 불가 후보는 표시하며, ‘전체 후보’에서는 제외 이유도 볼 수 있습니다. 반복 사용은 실행 시간표에서 별도로 확인합니다. 타격 및 효과 부여 시점은 추정이며 동일 대상 적중, 효과 소모·중첩까지 보장하지 않습니다.

정적 서버에서 `dist/`를 서비스하면 됩니다. 기존 Sites에 반영할 때는 `.openai/hosting.json`의 프로젝트 ID를 유지하고 Sites의 소스 동기화·버전 저장·배포 절차를 사용합니다. 이 프로젝트는 인증정보를 포함하지 않습니다.

## 바탕화면 바로 실행

바탕화면의 **도술 연계도** 아이콘을 누르면 이 프로젝트의 기존 서버를 종료하고 새 서버를 시작한 뒤 기본 브라우저를 엽니다. 주소는 `http://127.0.0.1:5173/`로 유지됩니다.

- 실행 파일: `scripts/launch.ps1`
- 서버 상태와 로그: `.local/server.json`, `.local/server.log`, `.local/server-error.log`
- 프로젝트의 절대 서버 경로가 확인된 Node 프로세스만 종료합니다. 다른 프로그램이 5173 포트를 점유하면 종료하지 않고 안내합니다.
- 기존 웹사이트와 로컬 주소의 저장 데이터는 별개입니다. 기존 빌드는 JSON으로 내보낸 뒤 로컬에서 가져오세요.

## 회귀 테스트

프로젝트 폴더에서 `node scripts/test.cjs` 또는 `npm test`로 전체 테스트를 실행합니다. 별도 패키지 설치가 필요하지 않습니다. Windows에서는 PowerShell/CIM 조회와 임시 로컬 서버 연결 권한이 필요합니다.

- 도술 자료·로컬 아이콘·그래프, 단일/범위 필터, 검색, 배치·삽입·교체·이동·되돌리기, 궁극기·기본 장착 조건
- 저장·불러오기·이전 JSON 호환·잘못된 파일 거부·CSV/JSON/DOT 내보내기, 저장 메뉴 외부 클릭/Escape 닫기
- 12계열 신식, 우선순위 시전, 충전·초기화·강압·격노, 효과 만료와 타격 경계, 실시간 후보/간트 구간
- 105개 도술 × 4개 공간 환경, 시간 보존·비중복·유한 수치·대상 상한, 미확인 자료의 보류 처리
- 엔진 불변식: 무작위 빌드의 시간표·충전·우선순위·타격·조건·검의 형상·집계·결정성과 v4 수정 재현
- 실제 HTTP 서버와 Windows 실행기 재시작, 다른 프로세스의 포트 보호 (별도 임시 프로젝트에서 검사)

궁극기 장착 조건이 잘못되면 엔진은 계산을 보류합니다. 일부 정보가 빠진 결과는 피해 계수 미확인을 0으로 표시하지 않고 계산 제외로 남깁니다.

방패 낙하의 타격 횟수와 휩쓸어 베기의 주변 공격·돌진은 설명을 반영합니다. 휩쓸어 베기는 첫 추정 타격 시점까지 시전 시작 때의 대상 위치로 이동하는 비교 가정입니다. 공격 반경·부채꼴 각도·미확인 대상 상한은 여전히 모델 가정이며, 은신의 동작 시간이나 방패 낙하의 피해 계수 등 미확인 게임 자료를 테스트 통과로 확정하지 않습니다.

모델 v3부터 생명의 흐름 등 비공격 도술은 검의 형상과 암습 쿨타임 감소를 만들지 않습니다. 공격 도술의 형상 획득은 여전히 적중을 가정하므로 빗나감·실제 적중 시각에 따른 차이는 반영하지 않습니다.
