# Community build benchmark

Snapshot: 2026-10-18, https://kkaebigg.com/deck/, current patch, all slot counts, votes >= 20. Pages 1–2 in descending vote order contained 23 qualifying builds; the next entry had 18. Previous-patch archive excluded.

Run from repository root, Node only, no external packages:

```sh
node scripts/benchmark-community.cjs --output community-benchmark.json
node community-benchmark.test.cjs
```

Options: `--fixture`, `--controls` (default 60 per group), `--iterations` (default 300 per search), `--output`. Two fixed seeds. `community-baseline.json` is a compact record; full report is generated by the command. Engine code and data versions affect results.

References never seed search and votes never enter the objective. Four explicit synthetic area layouts and one respawning target for single-target builds; fixed synthetic stats, not author stats. Single-target repeated profile runs are duplicates, not independent trials. Random controls use each group's represented ultimate families plus random normal skills. Only valid controls enter percentiles; ties count half. This measures discrimination against a random baseline, not global rank. Search uses the existing optimizer's default area objective and therefore must not be compared numerically to the benchmark's explicit layouts or single-target scores.

Card icon order is recorded separately from description. `baseNames` is the site's visual base-slot marking, not verified in-game equipment. Evaluation uses explicit `Q.fit` assumptions and records card-layout validation issues without changing the source. Build 159 has a separate description-order evaluation. Unsupported OFF/HP/manual opening policies are flagged, not silently simulated. Build 197 is author-labelled unverified despite high votes. Bug mentions remain flags.

Baseline findings: 23 valid fitted sets; 8 have unsupported execution policies. Two searches evaluated 775/768 layouts, found 0 exact reference sets, and their recommendations had at most 4/9 overlap. This budget does not prove unreachable combinations. Survival, level, breakthrough and author stats are not matched: do not treat the kill-only ordering as real-world superiority, especially for healing builds. No model tuning or held-out evaluation has been performed. Future train/test splits must group closely related variants to avoid leakage.

Additional discovery: the experimental encounter engine's no-zone default uses the same coordinates for different profile names. This benchmark supplies distinct coordinates; production search still uses its original default. Full simulation limitations are in `dist/encounter.js`.
